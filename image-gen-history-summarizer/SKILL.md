# AI生图总结

用这个 skill 分析一组 AI 生图记录，并把“生成过程、关键变化、方法论、提示词沉淀”整理成清晰的中文结果。

支持输入：

- 聊天记录
- prompt / negative prompt
- 参数截图
- 多轮结果图
- 带界面文字的截图
- 文件夹路径或文件夹链接

## 核心流程

1. 如果用户提供文件夹路径或文件夹链接，先将其中所有相关图片纳入材料范围。
2. 盘点材料来源：聊天文本、截图、结果图、参数信息、文件夹内图片。
3. 判断这些材料是单一路径迭代，还是包含候选分支。
4. 读取图片中的可见文字、提示词、参数、模型名、界面信息。
5. 对比每一轮图片和文字，提取变化：
   - prompt 增加了什么
   - prompt 删除了什么
   - negative prompt 是否变化
   - 参数是否变化
   - 主体、构图、风格、色彩、细节如何变化
6. 还原从初稿到修改、再到定稿的演进链路。
7. 将每条结论标记为 `明确` 或 `推断`。
8. 默认输出完整总结版：先给标准复盘，再给沉淀总结。

## 证据规则

- 用户聊天中明确写出的内容，算明确证据。
- 截图中能清晰读出的提示词、参数、说明文字，算明确证据。
- 图片之间肉眼可直接判断的明显变化，算明确证据。
- 文件夹中的图片，只要可读、可比对，同样算有效证据。
- 缺失的中间步骤、模糊的截图文字、未明说的设计意图，只能算推断。
- 绝不把猜测写成事实。

如果时间线不完整，明确写：

`时间线可能不完整，以下按当前最可信顺序整理。`

如果图片里的文字辨识度有限，明确写：

`截图中的部分文字辨识度有限，以下相关结论含一定推断成分。`

详细规则见 [references/evidence-rules.md](references/evidence-rules.md)。

## 默认输出结构

默认不需要用户额外补充说明。只要调用这个 skill，就输出完整结果，按下面顺序组织：

1. `一、内容概览`
2. `二、生成步骤复盘`
3. `三、关键调整点`
4. `四、可复用方法论模板`
5. `五、AI生图总结流程`
6. `六、可复用方法论`
7. `七、可复用提示词`
8. `八、仅适用于本项目的提示词`
9. `九、可直接使用的中文组合提示词`
10. `十、项目总结一句话`

前四部分是标准复盘版，后六部分是沉淀总结版。除非用户明确要求更短版本，否则不要省略后半部分。

### 前半部分：标准复盘版

适用于还原“这张图是怎么一步一步做出来的”，并且现在是默认必带内容。

固定输出四部分：

1. `一、内容概览`
2. `二、生成步骤复盘`
3. `三、关键调整点`
4. `四、可复用方法论模板`

其中 `二、生成步骤复盘` 的每一步都必须包含：

- `输入材料`
- `输入依据`
- `执行动作`
- `目的判断`
- `结果变化`
- `置信标记`

置信标记只能写：

- `置信标记：明确`
- `置信标记：推断`

### 后半部分：沉淀总结版

适用于把整套过程总结成更简单的流程、方法论和提示词，并且现在同样是默认必带内容。

固定输出以下部分：

1. `AI生图总结流程`
2. `可复用方法论`
3. `可复用提示词`
4. `仅适用于本项目的提示词`
5. `可直接使用的中文组合提示词`
6. `项目总结一句话`

要求：

- 用更短、更适合汇报图和总结页的写法
- 不需要重复长篇证据链
- 明确区分“可复用”和“仅适用于本项目”
- 所有提示词都使用中文

具体格式见 [references/output-template.md](references/output-template.md)。

## 何时缩短输出

只有在以下情况才缩短，不输出完整十部分：

- 用户明确说只要过程复盘
- 用户明确说只要总结图文案
- 用户明确说只要提示词
- 用户明确说要超短版 / 极简版 / 一句话版

否则默认输出完整十部分。

## 文件夹输入处理

- 如果用户提供文件夹路径或文件夹链接，默认遍历其中所有相关图片。
- 先判断它们是连续迭代，还是同一轮的候选分支。
- 如有必要，在结果开头简要交代：
  - 共检查多少张图
  - 主要来源于哪个文件夹
  - 是单一路径还是多分支
  - 图上文字是否大多可读

## 风格要求

- 全程使用中文。
- 说清楚“改了什么”和“为什么改”。
- 能把文字变化和视觉变化对应起来时，优先对应起来。
- 做总结版时，优先压缩成高信息密度、适合汇报展示的短句。
- 不要只复述原始 prompt，要解释图是如何收敛出来的。

## 快速执行规则

遇到这类请求时，按下面顺序处理：

1. 识别输入范围
2. 读图和读字
3. 还原时间线
4. 提取关键变化
5. 判断用户要“复盘版”还是“总结版”
6. 默认将两者合并输出
