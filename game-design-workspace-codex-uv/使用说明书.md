# 游戏设计工作台 / Game Design Workspace 使用说明书

## 1. 这是什么

游戏设计工作台（Game Design Workspace）是一个本地运行的小游戏设计工作台，用来把一份玩法大纲逐步整理成：

- 完整策划案
- 交互设计方案
- 可编辑 SVG 线框稿
- 总资产图
- 各界面视觉设计稿
- 可打包导出的项目资源

它适合策划、交互、UI 设计、玩法设计同学在本地快速产出和迭代方案。

## 2. 使用前准备

请先准备：

- 一台 Windows 电脑
- 可正常联网的环境
- 你自己的 `BABYLON_JWT_TOKEN`

## 3. 首次启动

通过 Codex 自动安装并启动。

## 3.1 通过 Codex 自动安装并启动

如果你希望让 Codex 直接帮你安装和启动，按下面步骤操作。

### 3.1.1 先复制 zip 到本地

从下面这个 EMC 地址：

```text
\\10.21.100.89\Project Snake\FF_UIAssets\【2026】\游戏体验\小游戏平台
```

把 `game-design-workspace-codex-uv.zip` 复制到你本地任意一个文件夹。

建议放到一个单独目录里，方便后续解压和管理。

### 3.1.2 在 Codex 新建会话

在 Codex 里新建一个会话，并确保：

- 权限选择“完全访问”
- 模型不低于 `5.4`

### 3.1.3 给 Codex 发送固定指令

把下面这段文字原样发给 Codex：

```text
请在当前项目目录里安装并启动这个本地包：game-design-workspace-codex-uv.zip

要求：
1. 先检查当前目录里是否存在 game-design-workspace-codex-uv.zip
2. 把它解压到当前目录下的 game-design-workspace-codex-uv 文件夹
3. 检查解压后是否包含 README.md、index.html、script.js、styles.css、local-server.py、start-local.bat、start-local-uv.bat、.env.example、api 文件夹
4. 如果 .env 不存在，就用 .env.example 创建 .env
5. 不要替我填写真实 token；只提醒我手动填写 BABYLON_JWT_TOKEN
6. 如果我确认 .env 已填写，再帮我启动 start-local-uv.bat；如果 uv 不可用，再告诉我该怎么处理
7. 启动成功后告诉我访问 http://localhost:8787/
8. 不要修改源码，除非我明确要求
```

### 3.1.4 Codex 问你要 Token 时怎么做

把上面的指令发给 Codex 后，它通常会提醒你填写 `BABYLON_JWT_TOKEN`。

这时你需要：

1. 打开 Taco
2. 进入设置页面
3. 找到开发者区域里的“复制 JWT Token”
4. 复制 `BABYLON_JWT_TOKEN`
5. 粘贴到 Codex 对话中

然后 Codex 会继续帮你完成：

- 创建 `.env`
- 写入你提供的 `BABYLON_JWT_TOKEN`
- 启动本地服务
- 打开游戏设计工作台网页

### 3.1.5 使用这种方式时的注意事项

- 只把 token 发给你自己的 Codex 会话
- 不要把 token 发到群里或发给别人
- 如果 Codex 还没拿到 token，它不会完成真正启动
- 如果你只想让 Codex 安装，不想让它修改任何功能，就继续坚持“不要修改源码”

## 4. 页面模块说明

页面主流程从上到下分成 5 个部分：

### 4.1 玩法大纲

你可以：

- 手动输入项目名称
- 粘贴玩法大纲
- 上传 `txt / md / json / csv / pdf / docx`
- 选择目标平台是横版还是竖版
- 点击“规范化玩法大纲”
- 点击“锁定”

建议玩法大纲至少包含：

- 游戏名称
- 核心玩法
- 玩家目标
- 留存方式
- 后续扩展方向

### 4.2 完整策划案

你可以：

- 选择策划案模型
- 点击“生成策划案”
- 手动编辑生成结果
- 下载 PDF
- 锁定当前策划案

生成后，系统会自动识别目标界面，并显示在“目标界面”区域。

### 4.3 交互设计方案

你可以：

- 选择交互案模型
- 点击“生成交互案”
- 在“完整 / 界面 / 流程 / 交付”四个标签里查看内容
- 手动编辑交互案
- 点击“刷新可视化”
- 下载 PDF
- 锁定交互案

### 4.4 可视化交互方案

这里用于生成可编辑 SVG。

你可以：

- 输入“当前 SVG 要求”
- 点击“生成可编辑交互 SVG”
- 点击“一键生成所有界面 SVG”
- 切换不同界面查看 SVG
- 导出 SVG
- 锁定 SVG

这部分重点是结构和交互表达，不是最终视觉稿。

### 4.5 界面视觉设计稿

这是最终出图区域，包含三类能力：

- 总资产生成
- 普通界面设计稿生成
- 设计稿编辑与确认

## 5. 推荐使用流程

建议按下面顺序使用：

1. 输入或上传玩法大纲
2. 规范化玩法大纲
3. 生成完整策划案
4. 检查并编辑策划案
5. 生成交互设计方案
6. 检查并编辑交互案
7. 生成可编辑 SVG
8. 上传画风参考图，填写生图关键词
9. 先生成总资产
10. 再生成普通界面设计稿
11. 如有需要，对设计稿做局部编辑
12. 确认无误后导出资源包

## 6. 如何生成设计稿

### 6.1 上传画风参考图

在“画风参考图”区域中：

- 最多支持 2 张图片
- 支持上传、拖拽、粘贴
- 参考图主要用于控制风格，不建议拿参考图直接定义具体功能布局

### 6.2 输入生图关键词

在“生图关键词”区域中填写希望的视觉方向，例如：

```text
治愈系、清爽、偏正式手游界面、层次分明、圆角面板、浅色背景、细节丰富
```

建议关键词重点描述：

- 风格
- 材质
- 配色
- 光感
- 界面气质

### 6.3 先生成总资产

总资产分为三类：

- UI 控件
- 背景设定
- 角色设定

建议先生成总资产，再生成普通界面设计稿。这样后续界面生图会更稳定。

### 6.4 生成普通界面设计稿

你可以：

- 生成当前界面设计稿
- 一键生成所有界面设计稿
- 切换设计稿标签查看不同界面
- 下载全部设计稿

## 7. 如何编辑设计稿

当某个界面已经生成设计稿后，可以点击：

- `编辑设计稿`

目前支持 4 种编辑操作：

- `删除控件`
- `替换控件`
- `添加控件`
- `补全缺口`

### 7.1 删除控件

适合删除当前界面中多余的按钮、面板、图标等元素。

### 7.2 替换控件

适合把某个已有控件替换成总资产图中的另一种控件样式。

### 7.3 添加控件

适合往已有界面中补加一个按钮、卡片、入口或其他 UI 控件。

### 7.4 补全缺口

适合修补界面里缺失、断边、破损、不连续的区域。

### 7.5 候选结果确认

编辑请求完成后，不会直接覆盖原图。

系统会先给出候选结果，你可以：

- `确认覆盖`
- `丢弃候选`

只有点击“确认覆盖”后，当前设计稿才会真正更新。

如果你只是想试试看效果，先看候选结果即可，不满意就丢弃。

## 8. 锁定功能怎么用

系统支持多种锁定，适合在方案稳定后防止误刷新。

### 8.1 锁定玩法大纲

避免玩法输入被误改。

### 8.2 锁定策划案

避免策划案被重新覆盖。

### 8.3 锁定交互案

避免交互案被重新覆盖。

### 8.4 锁定 SVG

固定当前可编辑 SVG 结果。

### 8.5 锁定总资产

固定当前总资产图。

### 8.6 锁定设计稿

这是比较重要的一项。

锁定设计稿后，会一起保存：

- 当前整组设计稿
- 当前激活界面
- 生图关键词
- 参考图
- 设计稿模型
- 总资产引用勾选状态

刷新页面后，锁定的设计稿和相关输入会自动恢复。

## 9. 导出功能

页面顶部和设计稿区域提供导出能力。

你可以导出：

- 策划案 PDF
- 交互案 PDF
- SVG
- 全部设计稿
- 项目资源包

“下载项目资源包”会尽量把当前项目中的核心产出统一打包，适合归档或传给其他人查看。

## 10. 自动生成功能

页面顶部有：

- `自动生成`

它会按平台设定的推荐流程自动推进生成步骤，适合已有明确玩法大纲时快速跑一遍全流程。

如果你需要更可控的结果，建议还是按模块逐步生成和检查。

## 11. 常见问题

### 11.1 页面能打开，但不能生成

优先检查：

- Codex 启动的服务窗口是否还开着
- 打开的地址是不是 `http://localhost:8787/`
- `.env` 是否已配置
- `BABYLON_JWT_TOKEN` 是否还是占位内容

### 11.2 端口被占用

如果 `8787` 已被其他程序占用：

- 关闭旧的服务窗口
- 再次启动

### 11.3 生图慢或失败

这通常和以下因素有关：

- 网络不稳定
- 模型服务响应慢
- 参考图质量不高
- prompt 太模糊

建议先优化：

- 参考图质量
- 生图关键词
- 总资产先生成完再做普通界面生图

### 11.4 编辑结果不理想

可以尝试：

- 缩小编辑框选范围
- 把一次大改拆成多次小改
- 优先使用“删除控件”或“补全缺口”
- 先确认总资产图是否合适

## 12. 使用建议

- 先出结构，再出视觉，不要一开始就反复改最终图
- 总资产尽量先稳定，再批量生成普通界面
- 每次只调整一个明显问题，结果会更稳
- 对重要阶段使用锁定，避免刷新后误丢
- 最终交付前，统一导出资源包留档

## 13. 安全提醒

- 不要把自己的 `.env` 发给别人
- 不要把自己的 token 发给别人
- 如果只是使用，不建议直接修改包内代码文件
- 使用完成后，保留导出的资源包即可
